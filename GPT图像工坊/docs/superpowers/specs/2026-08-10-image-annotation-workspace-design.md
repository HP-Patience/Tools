# 图片查看与标注编辑工作台设计

日期：2026-08-10
项目：GPT 图像工坊
状态：已由用户确认，待实现计划

## 1. 背景

当前项目已经具备两个核心能力：

- 文生图：前端调用 `/api/generate`，后端调用上游 `/v1/images/generations`。
- 图生图/编辑：前端上传图片并调用 `/api/edit`，后端以 multipart 方式调用上游 `/v1/images/edits`。

上游不是官方 OpenAI API，而是通过 ChatGPT 账号和 CPA 反向代理得到的兼容接口。已验证它对图片参数支持较少：`n`、`size`、`quality`、`output_format`、`background` 等参数不可依赖；图片生成和图片编辑都应只发送最保守字段。

用户希望增加个人使用场景下的图片查看与标注编辑能力：选择本地图片后可预览并编辑；生成结果可点击放大继续编辑；编辑时可画圈、方框、箭头、文字说明等；点击发送后把标注信息带给上游继续生成/编辑。

## 2. 目标

本次功能目标：

1. 图片可查看：本地选择图片、生成图片、编辑结果图片都可以点击放大查看。
2. 图片可标注：在放大工作台里支持矩形、圆形、箭头、自由画笔、文字注释。
3. 标注可管理：支持选择、拖动、缩放、删除单个标注、撤销、清空。
4. 注释可发送：每个重要标注可以附带文字说明，发送时追加到提示词。
5. 标注图可发送：把标注直接烘焙进 PNG 图片，再作为 `/api/edit` 的上传图片发送。
6. 文件可保存：保存发送给上游的标注合成图，也保存上游返回的 AI 编辑结果。
7. 保持兼容：继续只向 CPA 上游发送 `model`、`prompt`、`image` 这些保守字段。

## 3. 非目标

本次不做以下内容：

- 不迁移到 Next.js。
- 不引入数据库。
- 不做用户系统、云端历史、项目管理。
- 不支持官方 OpenAI mask、透明背景、局部编辑参数等高级字段。
- 不保存完整 Fabric.js 会话 JSON，暂不支持关闭页面后恢复可编辑标注对象。
- 不做多人协作或生产级权限控制。

## 4. 已确认决策

### 4.1 标注发送策略

采用“方案 C”：

- 前端把标注图形直接合成到图片像素里。
- 同时把标注说明追加到用户 prompt 后面。
- 后端仍调用 `/api/edit`。

这样最适合当前 CPA 反向代理，因为它已验证支持普通图片上传，但不应假设支持官方 mask 或结构化标注参数。

### 4.2 标注工具范围

采用“完整版”：

- 矩形
- 圆形
- 箭头
- 自由画笔
- 文字注释
- 颜色选择
- 线宽选择
- 撤销
- 清空
- 拖动/移动
- 缩放
- 删除单个标注
- 标注列表

### 4.3 保存策略

采用“方案 2”：

- 保存标注合成图。
- 保存 AI 编辑结果。
- 不保存完整会话历史。

### 4.4 Canvas 库

采用本地 Fabric.js：

- 将 Fabric.js 下载到 `static/vendor/` 本地引用。
- 不依赖 CDN，适合本地个人使用。
- 利用 Fabric.js 的对象选择、拖动、缩放、文本、画笔和 PNG 导出能力，减少手写 Canvas 的复杂度和 bug。

## 5. 用户体验设计

### 5.1 整体布局

新增“图片工作台”弹窗或全屏 modal。结构如下：

- 顶部栏：当前图片来源、关闭、保存、发送编辑等操作。
- 左侧工具栏：选择、矩形、圆形、箭头、画笔、文字、颜色、线宽。
- 中间画布：显示图片和标注内容。
- 右侧标注列表：展示标注编号、类型、颜色和说明文本。
- 底部或右侧操作区：撤销、删除选中、清空、导出/保存、发送编辑。

用户已经确认该布局方向：弹窗图片工作台 + 左工具栏 + 中间画布 + 右标注列表。

### 5.2 本地图片流程

1. 用户点击文件选择框选择图片。
2. 前端立即显示本地预览缩略图。
3. 用户可点击缩略图或“编辑/标注”按钮打开图片工作台。
4. 工作台加载该图片作为 Fabric canvas 的锁定背景。
5. 用户添加标注和说明。
6. 用户点击“发送编辑”。
7. 前端导出带标注 PNG，并把标注说明追加到 prompt 后提交 `/api/edit`。

### 5.3 生成图片流程

1. 用户输入 prompt 并生成图片。
2. 前端展示生成结果网格。
3. 每张结果图片都可以点击放大查看。
4. 放大后可进入同一个图片工作台继续标注。
5. 用户点击“发送编辑”后，以该生成图为底图继续调用 `/api/edit`。

### 5.4 编辑结果继续迭代

AI 编辑结果和生成结果行为一致：

- 可点击放大。
- 可重新打开工作台。
- 可继续画圈、画框、写说明。
- 可再次发送 `/api/edit`。

这样形成个人使用所需的连续迭代链路。

## 6. 前端设计

### 6.1 文件位置

主要变更集中在：

- `static/index.html`
- `static/vendor/fabric.min.js`

如果 `static/index.html` 继续膨胀明显，可在实现时再拆出本地 JS 文件，例如：

- `static/app.js`
- `static/annotation-workspace.js`

拆分只服务于本功能，不做无关大重构。

### 6.2 图片工作台状态

前端维护以下运行时状态：

- 当前底图来源：本地上传、生成结果、编辑结果。
- 当前底图 URL 或 Blob。
- Fabric canvas 实例。
- 当前工具：选择、矩形、圆形、箭头、画笔、文字。
- 当前颜色。
- 当前线宽。
- 标注对象列表。
- 撤销栈。

标注对象需要带 metadata：

- `id`：前端生成的唯一编号。
- `type`：rectangle、circle、arrow、brush、text。
- `note`：用户填写的说明。
- `color`：标注颜色。

### 6.3 工具行为

- 选择工具：用于选中、移动、缩放、删除对象。
- 矩形工具：拖拽创建矩形。
- 圆形工具：拖拽创建椭圆/圆形。
- 箭头工具：拖拽创建线段和箭头头部，可用 Fabric group 表示。
- 画笔工具：启用 Fabric freeDrawingBrush。
- 文字工具：点击画布添加 Fabric Textbox。
- 颜色/线宽：影响后续新建标注，也可在选中对象时应用到当前对象。

### 6.4 标注列表

右侧列表展示当前 canvas 中的标注对象。每一项包含：

- 标注编号。
- 标注类型。
- 说明输入框。
- 选中按钮。
- 删除按钮。

用户点击列表项时，同步选中画布对象；画布选中对象时，也同步高亮列表项。

### 6.5 导出

发送前执行：

1. 取消当前对象选中框，避免控制点进入导出图。
2. 将 Fabric canvas 导出为 PNG Blob。
3. 收集标注说明，生成追加 prompt。
4. 构造 `FormData`：
   - `prompt`：原始 prompt + 标注说明。
   - `model`：当前选择模型。
   - `count`：前端数量选择；后端仍通过循环实现，不传上游 `n`。
   - `image`：导出的标注 PNG。
   - `save_annotated`：可选布尔值，默认为 true。
5. POST 到 `/api/edit`。

## 7. 后端设计

### 7.1 保持上游请求保守

`image_gen.py` 继续只向上游 `/v1/images/edits` 发送：

- `model`
- `prompt`
- `image`

不发送 `size`、`quality`、`output_format`、`background`、`n`、mask 等字段。

### 7.2 保存标注合成图

`/api/edit` 增加或确认以下行为：

- 接收前端上传的图片，这张图片可能已经包含标注。
- 在调用上游前，把这张上传图保存到 `output/annotated_<timestamp>.png`。
- 调用上游成功后，继续保存返回图到 `output/edited_<timestamp>_<index>.png`。
- 响应中返回：
  - `annotated_file` 或 `annotated_url`
  - `images` 列表
  - 上游错误时保留清晰错误信息

如果实现时希望避免影响普通编辑，可使用 `save_annotated=true` 控制保存；默认对工作台发送启用。

### 7.3 错误处理

前端需要处理：

- 未选择图片就发送编辑。
- 图片加载失败。
- Fabric.js 加载失败。
- 画布导出失败。
- 上游超时或返回错误。
- 返回结果为空。

后端需要处理：

- 上传文件为空。
- 非图片文件或无法识别图片。
- 保存标注图失败。
- 上游 `/images/edits` 不可用或返回非预期结构。

错误显示应继续使用当前页面的错误区域，尽量展示上游返回的原始 JSON，方便用户自己调试 CPA 代理。

## 8. 数据流

### 8.1 标注编辑发送流程

```text
用户选择/点击图片
  -> 前端打开图片工作台
  -> Fabric.js 加载底图
  -> 用户添加标注和说明
  -> 前端导出标注 PNG
  -> 前端拼接 prompt + 标注说明
  -> POST /api/edit
  -> 后端保存 annotated PNG
  -> 后端调用 CPA 上游 /v1/images/edits
  -> 后端保存 edited PNG
  -> 前端展示结果
  -> 用户可点击结果继续编辑
```

### 8.2 Prompt 拼接格式

采用固定、简单、中文可读格式：

```text
{用户原始提示词}

标注说明：
1. 红色矩形：请增强这里的金属质感。
2. 蓝色圆圈：请让这里背景更干净。
3. 绿色箭头：请让边缘更锐利。
```

如果某个标注没有说明，可生成通用描述，例如：

```text
2. 红色圆形：请重点参考此处标注区域。
```

## 9. 测试方案

### 9.1 前端手动测试

- 选择本地图片后立即出现预览。
- 点击预览能打开工作台。
- 每种工具都能创建标注。
- 标注可移动、缩放、删除。
- 标注列表与画布选中状态同步。
- 撤销和清空可用。
- 导出 PNG 不包含 Fabric 控制点。
- 点击发送后进入 loading 状态，成功后展示结果。
- 生成图、编辑结果图都能继续打开工作台。

### 9.2 后端手动测试

- `/api/edit` 接收前端导出的 PNG。
- `output/annotated_*.png` 成功保存。
- `output/edited_*.png` 成功保存。
- 上游错误能原样或清晰地反馈到前端。

### 9.3 回归测试

- 原有文生图 `/api/generate` 不受影响。
- 原有普通图片编辑流程仍可用。
- Count 选择仍由后端循环实现，不向上游传 `n`。
- 不重新加入上游不支持的参数。

4. 实现矩形、圆形、文字、画笔工具。
5. 实现箭头工具。
6. 实现标注列表、说明输入、选中同步、删除。
7. 实现撤销、清空、颜色、线宽。
8. 实现导出 PNG 和 prompt 拼接。
9. 调整 `/api/edit` 保存 annotated PNG 并返回路径。
10. 做本地手动测试和 git 提交。

## 11. 成功标准

功能完成后，用户应能完成以下闭环：

1. 选择一张本地图片，页面立即显示出来。
2. 点击图片进入工作台。
3. 在图片上画圈、画框、箭头、文字说明。
4. 点击发送，项目把带标注的图保存下来并提交给上游编辑接口。
5. 页面显示 AI 编辑结果。
6. 点击 AI 结果继续进入工作台，继续标注和再次编辑。

该闭环稳定可用，即视为本功能第一版成功。
