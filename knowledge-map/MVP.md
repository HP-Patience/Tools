# 个人 AI 知识地图工具 — MVP

## 1. 产品定位

一个**在电脑本地由 Agent 维护、通过 GitHub Actions 部署到个人服务器、支持多设备登录查看的只读知识地图网站**。

用户只在电脑上使用自己习惯的 Agent 修改学习项目，通过自然对话将所学整理进知识文件。本地校验和构建后，将待发布内容推送到 GitHub，由 GitHub Actions 将构建产物部署到个人服务器。用户在电脑、手机和平板的浏览器中通过用户名和密码验证后，只读查看地图。

不内置聊天，不绑定特定模型，不按教材目录预设框架。

## 2. 学习原则与产品边界

- **框架属于用户。** 地图从空白开始，可以先根据用户的初步整体认识建立主干，再逐渐补充和修正。
- **多个来源汇入同一知识结构。** 教材、课程、文章和实践是知识来源，不决定地图的组织方式。
- **先建立初步整体框架，再深入局部与关联。** 不要求一开始掌握完整体系，也不让 AI 擅自填满未知部分。
- **Agent 帮助整理，不代替理解。** 不把 AI 知道的内容直接记录为用户已经理解的内容，不根据节点是否存在判断掌握程度。
- **允许不完整。** 无法确定归属的内容暂时待归类，未理解之处明确记录为疑问。
- **数据独立于工具。** 知识保存在本地文件中，不依赖某个特定 Agent 或展示服务。

## 3. 使用方式与架构

### 3.1 确定的使用边界

- **写入端：个人电脑。** 只有本地 Agent 修改知识文件；本地可预览和校验。
- **版本管理与发布入口：GitHub。** 通过提交和推送发起发布，网页不写回仓库。
- **部署执行端：GitHub Actions。** 将选定版本的静态构建产物部署到用户自己的服务器。
- **浏览端：多设备浏览器。** 电脑、手机、平板均可登录查看，不提供在线编辑。
- **服务器职责：静态文件服务、HTTPS 和身份验证。** MVP 不建设业务 API、数据库或服务器端 Agent。

### 3.2 发布链路

```text
电脑上与 Agent 对话
  → 修改知识文件
  → 本地校验、预览并构建静态产物
  → 推送源码、知识数据及对应待发布产物到 GitHub
  → GitHub Actions 校验待发布内容并部署
  → 个人服务器：HTTPS + 用户名/密码保护
  → 任意设备的浏览器只读查看
```

按用户提出的“本地构建产物”方式设计：第一版暂定将专用发布目录随对应源码和知识数据一起提交，Actions 读取该目录进行部署，不能依赖仅存在于电脑但未上传的文件。发布前须校验产物与知识源文件的一致性，避免修改知识后忘记重新构建。

“推送源码后由 Actions 构建再部署”作为后续可选简化，不在本版文档中擅自替换已约定的本地构建流程。实际发布目录、触发分支和服务器连接信息在实现部署时确定。

### 3.3 核心学习流程

1. 用户在电脑上打开学习项目，让 Agent 读取项目规则和已有地图。
2. 用户自然讲述本次所学，也可以粘贴一小段材料并附上理解或问题；来源选填。
3. Agent 对照已有地图，判断需要新增、补充、关联还是记录疑问。
4. Agent 按约定执行局部修改；新建大类、合并节点、移动分支等结构调整先由用户确认。
5. 用户在本地预览并检查变化，确认后构建、提交和推送发布。
6. GitHub Actions 部署成功后，用户在任意设备登录网站，打开或刷新页面查看已发布版本。

**本地修改不会立即出现在远程网站。发布成功才更新线上版本；未推送、未构建或部署失败时，线上仍保留此前版本。**

## 4. MVP 功能范围

### 4.1 学习项目模板与 Agent 规则

提供项目级 `AGENTS.md`，记录：

- 用户的学习习惯和知识组织原则。
- 知识文件的位置、格式与修改方法。
- 修改前先读取已有地图，优先补充现有概念，避免重复建点。
- 区分用户明确表达的内容、提供材料中的内容与 Agent 自行扩展的建议。
- 不确定的归属先待归类，疑问单独记录。
- 新建大类、合并节点、移动分支等结构调整需要用户确认。
- 对话中只做必要的简短追问，不把学习记录变成考试或表单。

`AGENTS.md` 保存工作规则，不承载全部知识内容。对于不会自动读取该文件的 Agent，由用户在开始对话时明确要求其读取。

**目标：更换 Agent 后，仍可按同一套规则继续整理知识。**

### 4.2 统一的知识数据文件

第一版使用结构明确的 JSON 作为地图的唯一数据源。具体字段与文件名在实现时确定，至少包含：

| 数据 | 内容 |
| --- | --- |
| 知识节点 | 稳定 ID、标题、简要解释、父节点 |
| 跨节点关系 | 起点和终点节点 ID、关系类型、关系说明 |
| 学习疑问 | 尚未理解或需要继续探索的问题 |
| 学习来源 | 可选，同一节点可关联多个来源 |
| 更新信息 | 创建时间、修改时间，用于辅助标识变化 |

要求：

- 同一知识点不因来自不同教材而重复建立。
- 节点重命名或移动后，稳定 ID 不变，关联不因标题变化而失效。
- 支持空白地图、多个顶层分支和待归类内容。
- 不设置自动推断的掌握度分数。

**目标：知识独立于 Agent 与查看器，后续可迁移。**

### 4.3 思维导图主界面

提供一个以地图为主的工作台，不设内置聊天面板。

| 功能 | 行为 |
| --- | --- |
| 树状主干 | 展示整体知识框架 |
| 展开与折叠 | 在全局总览和局部细节之间切换 |
| 缩放、平移、回到全图 | 方便浏览不同规模的地图 |
| 搜索定位 | 按概念名称搜索并定位节点 |
| 节点详情侧栏 | 查看解释、疑问和来源 |
| 跨节点关系 | 选中节点时展示相关连线与说明，避免默认满屏交叉线 |
| 待归类区域 | 容纳暂时无法确定位置的知识 |

第一版只读展示，由电脑上的 Agent 统一负责知识修改。界面需适配电脑、手机和平板；移动端支持触控浏览，节点详情使用适合窄屏的面板，搜索和折叠操作不依赖鼠标悬停。

**目标：既能看整体，也能顺着关系深入查看。**

### 4.4 本地预览与线上版本更新

区分两种使用场景：

- **本地预览：** 监听知识文件变化，校验通过后重新加载，尽量保留当前展开状态与浏览位置。
- **线上查看：** 加载已部署的静态快照；部署成功后打开或刷新页面获取新版本，不监听用户电脑文件，不要求常驻连接或实时推送。
- 页面显示发布版本标识和构建时间，便于判断当前正在查看哪一版内容。
- 本地预览高亮相对上次有效加载的新增和修改；首次加载不将全图当作新增。
- 线上第一版不承诺跨设备同步“已读变化”或浏览进度，也不维护每台设备的版本差异历史。
- 为入口与数据设置合适的缓存策略，确保发布后刷新能加载同一版本的页面与知识数据。

**目标：本地检查方便，线上发布边界清楚，各设备查看同一份已发布地图。**

### 4.5 数据校验与恢复

本地预览、构建和发布前执行数据校验，至少检查：

- JSON 及数据结构是否有效。
- 节点 ID 是否重复。
- 父节点和关联节点是否存在。
- 父子关系是否成环。
- 待发布知识数据是否与当前知识源文件一致。

出现问题时：

- 显示明确错误，方便用户交给 Agent 修复。
- 校验失败时阻止构建或部署，不覆盖线上正常版本。
- 本地预览保留最后一次有效展示；未提交的有效知识数据保留本地恢复副本。
- 已提交知识内容通过 Git 历史恢复；服务器保留上一版有效发布产物，以便发布回滚。

**目标：错误修改、构建失败或部署失败都不破坏当前可用版本。**

### 4.6 GitHub Actions 自动部署

- 仅指定的发布分支推送或手动触发可以部署；不让任意分支和未受信任的 PR 获得部署权限。
- 部署前校验知识数据、产物完整性及源数据一致性。
- 部署凭据通过 GitHub Actions Secrets 配置，不写入仓库、前端代码或构建产物。
- 通过 SSH 部署时验证服务器主机密钥，使用仅能操作指定发布目录的部署账号。
- 仅上传网站所需的构建产物，不发布整个仓库、Git 元数据、本地备份、Agent 对话记录或凭据文件。
- 先上传完整的新版本，再切换对外服务的版本；失败时保留旧版，不先清空线上目录。
- 串行部署并检查版本顺序，避免较早的部署覆盖较新的发布。
- 提供部署状态和基本回滚说明，不另做部署管理后台。

**目标：用户只需在电脑完成发布提交与推送，无需每次手动登录服务器上传。**

### 4.7 简单身份验证

- 单个个人账号，以用户名和密码保护访问，不做注册、找回密码、角色权限或多用户系统。
- 优先采用服务器层的 HTTP Basic Auth，配合 HTTPS；第一版接受浏览器原生认证提示，不开发自定义登录页面。
- 验证必须发生在服务器端，不能仅由前端密码框控制显示。
- 保护整个站点，包括地图数据文件、含知识内容的脚本和附件，不能只保护首页。
- 禁止通过另一个未受保护的静态端口或路径绕过验证。
- 密码使用强密码；认证配置保存密码哈希，不向浏览器下发认证密码或哈希，不将其提交进仓库。
- 密码更换通过服务器配置完成，不承诺应用级会话管理和自定义退出登录功能。
- 仓库暂按私有仓库规划；若今后开放源码，需先将个人知识数据与公开代码分离。
- 服务器软件优先沿用现有环境；具体选择及证书配置在了解服务器情况后确定。

**目标：本人可从多设备访问，未认证访问者不能直接读取知识内容。**

## 5. 第一版明确不做

| 暂不做 | 原因 |
| --- | --- |
| 内置聊天、模型 API 接入 | 直接使用外部 Agent |
| 教材目录自动生成框架 | 框架由用户从零建立 |
| AI 一键生成完整学科体系 | 不以 AI 的知识替代用户的理解 |
| 整本教材、视频、网页自动解析 | 先验证对话整理的核心流程 |
| 图上手动编辑 | 第一版由 Agent 统一修改，避免双端写入冲突 |
| 自动掌握度评分、出题、复习计划 | 暂不扩展为完整学习平台 |
| AI 自主大规模重组地图 | 结构主导权保留给用户 |
| 复杂账号系统、双向云同步、多人协作、公开分享 | 只做个人账号验证和多设备只读查看 |
| 复杂知识库管理、插件和大量视觉主题 | 不属于核心闭环 |

第一版支持：**一个学习项目、一张知识地图、多个顶层分支、一个个人账号、多设备只读访问。**

## 6. 典型使用示例

用户对 Agent 说：

> 今天学了过拟合，帮我整理进现有地图。模型复杂度为什么会影响过拟合，我还没弄懂，先记成疑问。

预期行为：

1. Agent 读取项目规则和已有地图。
2. 如果已有“过拟合”节点，则补充现有节点；否则在明确的归属下新增，归属不清时询问或待归类。
3. 保留用户表达的理解，将尚未弄懂的问题记为疑问。
4. 与已有节点建立关系时，不将未经确认的推断当成用户已经理解的事实。
5. 按规则完成文件修改后，本地预览更新；确认后完成本地构建、提交和推送。
6. GitHub Actions 部署成功后，用户在手机或其他设备登录网站，打开或刷新页面，查看新版本的节点、关联和未解决的问题。

## 7. MVP 验收标准

### 功能验收

- 空白知识文件可以正常打开，并显示空状态。
- Agent 按规则修改后，本地预览无需人工搬运即可更新。
- 节点可以展开、折叠、搜索定位，详情和来源可查看。
- 跨节点关系能够按需显示。
- 电脑、手机和平板布局可用，移动端可以触控浏览和查看节点详情。
- 本地本次新增与修改可以识别和检查，线上可查看发布版本与构建时间。
- 有效的本地构建产物推送后，Actions 能部署到个人服务器；发布后刷新页面可查看新版本。
- 本地修改未发布时，线上不会错误地显示未发布内容。
- 数据无效、产物与源数据不一致或部署失败时，线上旧版仍可访问。
- 本地知识数据可恢复，已提交内容可从 Git 恢复，线上发布可回滚。
- 未认证或密码错误时，页面及直接访问的数据、附件等受保护资源均不可读取。
- 通过 HTTPS 使用正确用户名和密码，可以在不同设备查看地图。
- 仓库和构建产物不包含部署密钥、认证密码或服务器认证密码哈希。
- 服务器只公开构建产物，不公开整个项目目录或未受保护的旁路入口。

### 学习体验验证

用一个正在学习的主题连续使用几次，检查：

1. **表达成本：** 用户能否自然讲述所学，而不必先整理成正式笔记？
2. **修改准确性：** Agent 能否合理定位内容、保留用户原意，而不要求用户不断纠错？
3. **回看价值：** 用户能否看清整体结构、新增知识和仍未理解的地方？
4. **结构主导权：** 用户能否接受、拒绝或修正结构调整，而不是被动接受 AI 分类？

## 8. 核心成功标准

**用户主要依靠自然对话，就能让一张由自己主导的知识地图持续生长，并且回看时真正有用。**

本版优先做好“准确、可控地维护已有知识地图”，而不是“自动生成大量节点”。
